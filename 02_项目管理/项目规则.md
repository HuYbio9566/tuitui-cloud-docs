# 项目边界

- 本目录仅属于推推产品。
- 云盘产品位于同级目录 `../云盘`，不属于本项目。
- 除非用户明确要求跨项目操作，否则不要读取、搜索或修改 `../云盘` 中的文件。
- 新增代码、设计稿和报告前，先确认内容确实属于推推产品。

# 项目知识库

- 每次在本项目开启新任务，先阅读 `02_项目管理/00-项目知识库/README.md`。
- 按任务类型继续读取 `02_项目管理/00-项目知识库/PROJECT_BRIEF.md`、`DECISIONS.md`、`EVIDENCE_INDEX.md`、`OPEN_QUESTIONS.md` 和相关设计/规格文档。
- 新任务使用 `02_项目管理/00-项目知识库/TASK_BRIEF.md` 建立任务文件；完成后使用 `RETRO_TEMPLATE.md` 做复盘。
- 用户确认的方案、版本、范围和回滚决定必须写入项目文件，不能只留在对话上下文。
- 截图和临时参考资料复制到 `03_设计资料/证据与资料/` 后才能作为长期证据引用；项目管理区只保存证据索引和结论。
- 版本变更同步维护 `02_项目管理/08-版本与发布/当前版本.txt`、`版本历史.md` 和 `02_项目管理/00-项目知识库/CHANGELOG.md`。


# 项目管理库

- 以产品生命周期设计的 Obsidian 风格项目管理骨架位于 `02_项目管理/`，新任务先读取 `02_项目管理/README.md`，再读取 `00-项目驾驶舱/项目驾驶舱.md`。
- 新任务按“产品战略 → 用户与场景 → 需求与路线图 → 知识与内容 → 设计与原型 → 原型与实现 → 质量与验收 → 版本与发布 → 决策与复盘”选择目录，不使用旧的通用分类作为新入口。
- `02_项目管理/00-收件箱/` 只接收待判断材料；不得自动把聊天、截图或参考文档归档。
- 发现可能有长期价值的材料时，先向用户说明材料、拟存位置和保存理由，等待明确确认后再复制或移动。
- 未确认的材料不写入项目管理库；临时截图默认不保存。
- `02_项目管理/templates/` 中的模板用于任务启动、会议记录和复盘。
