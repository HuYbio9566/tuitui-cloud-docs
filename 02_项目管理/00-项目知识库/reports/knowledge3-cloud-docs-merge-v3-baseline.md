# 知识库 3.0 线上基线逆向调研

## 面向云文档合并第三次升级的设计、交互与开发基线

日期：2026-08-04 · 产品：推推云文档 / 企业知识工作台 · 当前产品版本：1.2.1

## 结论先行

这次合并升级应该对齐“知识库 3.0 的产品语法”，而不是把知识库页面简单嵌进云盘。线上语法可以概括为：

> 企业级三段导航 + 白色高密度内容区 + 文字 Tab/列表优先 + 单一蓝色动作 + AI 作为跨模块工作层。

用户始终沿着“我在哪个模块 → 我正在看什么范围 → 我能做什么动作”前进。文件是可管理的内容对象，知识库是可问答/可治理的范围对象，AI 是跨对象的工作方式；三者不能再用一套含糊的“文件/空间/知识”层级互相替代。

本报告将结论分成三类：已观察（来自截图、项目证据和 HTML）；高置信推断（多个页面/代码结构反复出现）；待实测（需要在线上客户端补证，当前不应写成产品事实）。

## 2. 线上 3.0 的信息架构反推

### 2.1 两层导航，不是单层侧栏

全局企业入口 → 推推知识工作台 → 新任务/AI、知识库、技能、专家、连接器、云盘、更多。
知识库 → 我的知识库/知识广场 → 知识库详情 → 库内文档与本库问答。
AI 工作台 → 找答案/办任务/写文档 → 引用答案、确认执行、可编辑草稿 → 文档或知识资产。

### 2.2 合并后的对象边界

| 对象 | 用户心智 | 核心动作 | 不能混淆 |
| --- | --- | --- | --- |
| 文件 | 原始资产/载体 | 上传、下载、移动、分享、预览 | 不等于知识范围 |
| 文档 | 可阅读/编辑内容 | 打开、编辑、版本、引用 | 不等于文件夹或知识库概览 |
| 知识库 | 有权限的文档集合与问答范围 | 问答、治理、加入、发布、复核 | 不等于云盘目录 |
| AI 工作台 | 跨对象完成工作的方式 | 找答案、办任务、写文档 | 不单独拥有一套资料层级 |
| 连接器 | 外部系统数据入口 | 授权、同步、撤销、健康检查 | 不用分享箭头语义替代 |

第三次升级的主线应是：文件资产 → 文档内容 → 知识资产 → AI 工作 → 结果沉淀。导航入口可以合并，但对象语义和权限边界不能合并掉。

## 3. 视觉基线

### 3.1 已确认的气质

- 桌面企业工作台，不是营销首页；高频信息以列表、目录和行布局承载。
- 内容区以白色为主，侧栏/外部空间使用浅灰或暖灰区分层级。
- 选中、链接、主动作使用单一蓝色；成功/警告/危险只表达真实状态。
- 低装饰、低阴影、轻边界；信息密度偏高但不拥挤。
- 中文系统字体，标题清楚、正文紧凑；标题/范围/动作同一水平路径。

现有项目 DESIGN.md 已给出可执行锚点；第三次升级建议统一到以下语义 token。颜色最终值仍需线上取样（待实测）：

## 4. 组件与交互规范

### 4.1 全局框架

- 保持 68px 全局 rail + 272px 产品侧栏 + 主工作区的三段连续骨架；三段之间不留 gap，不做三个独立悬浮卡。
- 顶部栏约 52px，标题/模块 Tab 占主位，右侧只放主动作和必要辅助动作。
- 侧栏导航项约 36px 高、8px 圆角；选中使用浅蓝实体面与文字蓝，不依赖阴影。
- 桌面级工具架在 ≤760px 收起为移动导航；禁止页面级横向滚动。

### 4.2 知识库列表

- 顶栏直接呈现“我的知识库 / 知识广场”文字 Tab；当前 Tab 有清晰文字/底部强调，不要再造大卡片标题。
- 列表筛选至少支持：全部、我创建的、我加入的；“待复核”可作为治理角色的权限化筛选。
- 知识库项要同时显示：名称、描述/用途、文档数量、负责人/参与关系、密级/发布状态、最近更新时间。
- 推荐问题是辅助入口，不应抢过知识库名称与主动作；高密度场景优先平面行布局，只有需要比较/独立点击时才使用卡片。
- 主动作固定为“本库问答/查看文档/分享或加入”，顺序按风险从低到高；删除、发布、外部分享必须进入确认流。

### 4.3 知识库详情

- 顶部只保留知识库名称、描述、密级/问答状态和返回/AI 主动作。
- 首屏信息分为“库内文档”和“热门问题/本库问答”两栏；文档行支持打开、收藏、分享、下载、更多。
- 打开文档后必须携带面包屑：知识库 → 文档；从 AI 引用回跳时保留来源上下文。
- “本库问答”明确写出“仅引用当前知识库”，发送前显示范围 chip；不能让用户误以为会搜索全组织。

### 4.4 AI 工作台

- 默认入口保留三模式：找答案/对话、办任务、写文档；模式切换是文字 Tab/段控件，不做三张营销卡。
- 输入器固定在工作区底部，工具栏顺序为：工作空间/知识范围 → 来源 → 技能 → 设置；发送按钮保持固定可见。
- 对话结果必须有来源标题、更新时间、权限过滤说明和引用片段；无来源时明确拒答/请求补充。
- 任务先展示目标、步骤、资料范围、连接器、预期产物，再按风险分级请求确认；不可把“生成计划”直接当“已执行”。
- 写作模式输出可编辑草稿，写入前显示差异、目标位置、权限、密级和复核人。

### 4.5 状态和反馈

| 组件 | 必须覆盖 |
| --- | --- |
| 知识范围选择器 | 推荐范围、当前文档、指定知识库、无权限/空范围 |
| 来源引用 | 加载、可展开、失效、权限变化、无来源 |
| 任务时间线 | 草稿、待确认、排队、执行中、暂停、阻塞、部分完成、失败、完成、取消 |
| 沉淀面板 | 新建文档、追加已有文档、权限不足、密级待复核、写入成功 |
| 文档行 | hover、键盘 focus、收藏、更多菜单、删除确认、空状态 |
| 连接器 | 未授权、同步中、健康、授权过期、撤销、失败重试 |

动效只表达反馈与来源关系，单次 120–190ms；按压使用 scale(.98)；prefers-reduced-motion 下移除位移与循环动效。

## 6. 第三次升级的推荐切片

### P0：先对齐线上语法并打通可信闭环

1. 导航与对象统一：保留全局入口，产品侧栏固定为新任务/知识库/技能/专家/连接器/云盘/更多；明确文件、文档、知识库三种对象。
2. 知识库列表/详情重排：我的知识库/知识广场 Tab、筛选、文档行、热门问题、本库问答，统一白色通栏和单一蓝色。
3. 范围—来源契约：所有 AI 入口都显示当前范围；回答显示引用快照、更新时间、权限状态；无来源明确拒答。
4. 结果沉淀：答案/任务/写作均支持进入新建文档、已有文档或知识库草稿；写入前展示差异和目标权限。

### P1：把线上 3.0 的治理能力接上合并工作台

- 知识治理清单：重复、过期、缺口、公开风险。
- 任务暂停/失败/部分完成和恢复。
- 角色化复核：发起人、复核人、知识负责人、管理员。
- 连接器健康、授权到期、撤销与最小权限。

### P2：不要在本次升级前置

- 大规模专家/技能市场扩展、多模型自由切换、复杂流程画布、全量连接器迁移、装饰性首页重做。

## 7. 开发交接信息

### 7.1 建议数据模型

    KnowledgeBase { id, name, description, ownerId, visibility, classification,
      status, documentCount, updatedAt, permissions[] }
    Document { id, kbId?, driveFileId?, title, kind, version, status,
      ownerId, reviewerId?, updatedAt, sourceSnapshotId? }
    SourceSnapshot { id, sourceType, sourceId, title, excerpt, updatedAt,
      permissionDecision, capturedAt, contentHash }
    Task { id, mode, goal, scopeIds[], stepIds[], riskLevel, status,
      createdBy, reviewerId?, outputIds[], idempotencyKey }
    TaskStep { id, taskId, action, inputs[], sourceIds[], status, retryCount,
      startedAt?, completedAt?, errorCode? }
    AuditEvent { id, actorId, action, objectType, objectId, scopeIds[],
      confirmationToken?, createdAt }

### 7.2 任务状态机最小实现

    draft → review → queued → running → complete
                         ↘ paused → running
                         ↘ blocked → review / cancelled
                         ↘ partial → resume / complete
                         ↘ failed → retry / adjust-scope / restart

写入、分享、发布、删除属于高风险动作：必须有一次性确认令牌或二次授权；每一步使用幂等 ID，避免重试造成重复写入。

### 7.3 前端组件契约

- AppShell：管理 rail/sidebar/main 三段宽度与移动端折叠。
- ModuleTopbar：模块标题、文字 Tab、主动作；不承载业务卡片。
- KnowledgeScopePicker：范围选择、权限提示、空范围态。
- SourceCitation：引用标题、片段、更新时间、权限状态、失效态。
- KnowledgeBaseList/Row：筛选、排序、密级、负责人、文档数。
- KnowledgeBaseDetail：文档行、热门问题、本库问答。
- TaskTimeline：步骤输入/来源/状态/输出/恢复动作。
- DepositReview：差异预览、目标位置、权限/密级/复核人、确认。
- ConnectorHealth：授权与同步状态、撤销/重试。

事件命名建议：kb_viewed、kb_scope_selected、source_opened、answer_feedback_submitted、task_plan_confirmed、task_step_retried、task_recovered、deposit_review_opened、deposit_confirmed、connector_auth_expired。

## 8. 验收矩阵

| 验收面 | 通过标准 |
| --- | --- |
| 视觉 | 单一蓝色；白色通栏；三段骨架连续；静态内容无大阴影/渐变/纹理 |
| 导航 | 3 秒内辨认当前模块、当前范围和主动作；返回路径不丢上下文 |
| 知识库 | Tab/筛选可用；列表显示负责人/文档数/密级/更新时间；详情只显示当前库文档 |
| AI | 无来源明确拒答；引用可展开；范围和权限始终可见 |
| 任务 | 高风险动作逐项确认；暂停/失败/部分完成可恢复；重试不重复写入 |
| 沉淀 | 新建/追加目标可选；差异、来源、权限、密级和复核人可见 |
| 响应式 | ≤1180px 目录 2 列；≤760px 单列；触控目标 ≥44px；无页面横向滚动 |
| 无障碍 | 可键盘访问；focus-visible；Tab/菜单有语义；减少动效设置生效 |
| 安全 | 检索前权限过滤；审计记录范围、来源、模型/版本和动作；越权测试 0 次 |

## 最终设计判断

第三次升级的关键不是把页面做得更“像截图”，而是把截图背后的秩序保留下来：导航稳定、对象边界清楚、范围和来源透明、动作有风险分级、结果能沉淀。只要这五件事成立，云盘与云文档合并就会自然落在知识库 3.0 的工作台语法里，而不会变成又一套平行的信息架构。
