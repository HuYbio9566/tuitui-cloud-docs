# 项目背景与产品简报

## 项目身份

- 项目：推推优化
- 产品范围：推推云文档/企业知识工作台原型、设计评审、版本归档和在线展示。
- 项目边界：不读取、不修改同级独立目录 `../云盘`。
- 当前记录日期：2026-08-03。

## 用户与工作问题

推推面向需要频繁查询企业资料、推进项目工作、生成文档和维护知识资产的企业知识工作者。当前主要问题是：

- 企业资料分散在文档、知识库和连接器中。
- 用户不知道答案使用了哪些来源、是否仍有权限。
- 找到答案后仍要人工整理成任务、文档或知识资产。
- 复杂任务涉及多个步骤，但缺少确认、异常恢复和责任记录。
- 项目设计和迭代历史容易停留在单次聊天或 Eagle 临时文件里，导致新任务无法快速复用上下文。

## 产品价值锚点

> 在权限边界内，把企业知识转成可引用答案、可控任务和可沉淀文档，并保留来源、责任和版本记录。

## 当前产品模型

### 三种 AI 工作模式

1. 找答案：基于权限内知识快速回答，展示引用和范围。
2. 办任务：把复杂目标拆成步骤，执行前确认关键动作。
3. 写文档：根据企业知识生成可继续编辑的文档草稿。

### 核心闭环

```text
提出问题/目标
→ 选择知识范围与权限
→ 获取来源可追溯的答案或计划
→ 人工确认关键动作
→ 完成任务/生成文档
→ 沉淀为可复用资产
```

## 当前阶段判断

现有 HTML 已能演示三模式入口、知识库、文档、任务和 AI 历史等交互，但主要仍是前端原型。真实模型、连接器执行、后端权限、持久化、审计和 GitHub 发布流程需要后续独立实现。

因此后续任务要明确标注：

- `prototype`：仅改变 HTML/CSS/JS 原型状态。
- `product`：涉及真实数据、权限、接口或持久化。
- `release`：涉及版本快照、Git commit、tag、GitHub Pages 或发布。

## 目标用户角色

| 角色 | 典型任务 | 关键成功结果 |
| --- | --- | --- |
| 项目负责人 | 汇总项目进展、识别风险、生成待办和周报 | 节省整理时间，责任人清晰 |
| 业务/行政人员 | 查询报销、采购、审批和制度要求 | 答案有来源且不越权 |
| 知识负责人 | 处理重复、过期、缺口和密级风险 | 知识资产持续可用 |
| 管理员/复核人 | 审核高风险动作、追踪任务和权限 | 谁做了什么可审计 |

## 当前最重要的三个场景

1. 制度/流程问答：问题 → 权限范围 → 引用答案 → FAQ/文档草稿。
2. 项目周报任务：目标 → 计划 → 确认 → 执行 → 风险/待办 → 周报。
3. 知识库治理：扫描 → 重复/过期/缺口/公开风险 → 清单 → 逐项确认。
