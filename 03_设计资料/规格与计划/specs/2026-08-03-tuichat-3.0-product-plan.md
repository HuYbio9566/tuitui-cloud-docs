# 推推 3.0 产品迭代规划

日期：2026-08-03

## 1. 版本判断

### 1.1 用户价值是否成立

成立，但目前只完成了“入口和交互原型”，还没有完成企业级工作闭环。

当前原型已经验证了三个需求方向：

- 用户希望在权限内知识中快速找到可信答案。
- 用户希望把复杂工作交给 AI 拆解，而不是只得到一段文本。
- 用户希望把答案或任务结果继续沉淀成文档、知识库资产。

3.0 必须验证的不是“用户是否喜欢三个模式”，而是下面这条闭环是否成立：

```text
提出工作目标 → 选择知识/权限范围 → 得到可追溯结果
→ 人工确认关键动作 → 完成工作 → 沉淀为可复用资产
```

如果只能回答，产品像搜索/聊天工具；如果能执行但没有权限、来源和确认机制，企业不会放心使用；如果能生成但不能沉淀，价值无法复利。

### 1.2 3.0 价值锚点

| 项目 | 定义 |
| --- | --- |
| 产品 | 推推企业知识工作台 3.0 |
| 为谁 | 需要频繁查制度、做项目协同、产出文档的企业知识工作者；其次是知识负责人和管理员 |
| 解决问题 | 企业资料分散、权限复杂，用户找到信息后仍要人工整理、确认和同步 |
| 提供价值 | 在权限边界内把知识转成可引用答案、可控任务和可编辑文档，并保留责任、来源和审计记录 |
| 核心差异 | 不是“更会聊天”，而是“答案—行动—沉淀”一体化，且每个关键动作可解释、可确认、可追溯 |
| 3.0 成功标准 | 用户能在一个工作会话内完成一次真实工作，而不是只生成一段演示文本 |

## 2. 版本策略

### 2.1 版本主题

**可信工作闭环：从问答原型到可控执行。**

不把 3.0 定义为“增加更多技能、专家和连接器”，也不以重做首页视觉为主线。3.0 的核心是把已有能力变成可靠的产品契约：

1. 来源可见：回答和任务都能知道用了什么资料、更新时间和权限状态。
2. 边界可控：执行前明确范围、写入/分享等高风险动作逐项确认。
3. 结果可复用：结果能进入文档或知识库，并保留版本、来源和责任人。
4. 异常可恢复：权限变化、连接失败、资料不足时，不丢结果、不静默失败。

### 2.2 三模式优先级

三模式保留，但不平均投入：

1. **找答案：P0 主入口**
   - 负责证明“权限内知识 + 可靠来源”的基础价值。
2. **办任务：P0/P1 核心差异化**
   - 负责证明“AI 能完成多步骤工作”，是 3.0 的主要升级点。
3. **写文档：P1 结果承接**
   - 负责把答案和任务结果变成可编辑、可复核、可沉淀的资产。

建议继续保留首页默认“找答案”，因为它的理解成本最低；从任务/负责人待办等场景进入时，可把默认模式切换为“办任务”。

## 3. 目标用户与关键场景

### 3.1 首要用户

- 项目负责人：汇总进展、识别风险、生成待办和周报。
- 业务/行政人员：查询制度、采购、报销、流程要求。
- 知识负责人：维护知识库、处理过期/重复/缺口内容。

### 3.2 3 个必须打通的核心场景

#### 场景 A：制度问答

用户提出“软件订阅如何报销”，系统限定权限范围，返回结论、来源、更新时间、适用条件和不确定项；用户可以一键沉淀为 FAQ 草稿。

#### 场景 B：项目周报任务

用户提出“汇总本周项目进展，标出风险并生成负责人待办”，系统先展示计划和资料范围，用户确认后执行，遇到权限变化或连接器失败时暂停并允许重试/跳过/保留部分结果。

#### 场景 C：知识治理任务

知识负责人发起“整理知识库”，系统识别重复、过期、缺口和密级风险，生成清单和建议动作；涉及删除、发布、分享必须逐项确认。

## 4. 迭代范围与阶段

建议按 4 个交付阶段推进，整体 10–12 周；每阶段都必须有可运行版本和验收数据。

### Phase 0：价值与数据基线（第 1 周）

目标：确认做的是高频真实工作，不是演示需求。

交付物：

- 3 个核心场景的用户任务脚本和成功/失败样例。
- 现状基线：问答成功率、来源点击率、任务完成率、人工返工时间。
- 知识库、文档、权限、角色和连接器的最小数据模型。
- 3.0 范围冻结清单和明确不做项。

验收门槛：

- 至少 5 位目标用户完成访谈或可用性走查。
- 每个核心场景至少有 10 条真实或脱敏样例。
- 每条答案/任务都能定义“什么算成功”。

### Phase 1：可信问答基础（第 2–4 周，P0）

目标：先建立用户对“答案可信且权限正确”的信任。

产品：

- 统一知识范围选择：推荐范围、当前文档、指定知识库。
- 回答展示来源标题、更新时间、权限过滤说明和引用片段。
- 无可用来源时明确拒答或请求补充，不生成伪确定答案。
- 支持答案反馈：有用/无用、原因和纠错入口。
- 支持一键沉淀为 FAQ/文档草稿，保留来源快照。

技术：

- 权限过滤在检索前完成，不能只依赖前端隐藏。
- 统一引用对象和来源快照结构。
- 记录检索范围、命中文档、模型版本和回答版本。

验收指标：

- 权限越权测试 0 次。
- 关键场景来源覆盖率 ≥ 90%。
- 用户能在 10 秒内找到至少一个可验证来源。
- 无来源问题的明确拒答率 ≥ 95%。

### Phase 2：可控任务执行（第 4–8 周，P0）

目标：把“办任务”从页面状态升级为可恢复的执行系统。

产品：

- 任务计划：目标、步骤、资料范围、连接器、技能、预期产物。
- 执行前确认：只读、写入、分享、发布、删除等动作分级提示。
- 任务时间线：每一步显示输入、来源、状态、输出和责任人。
- 异常状态：资料不足、权限变化、连接器失败、模型失败、部分完成。
- 恢复操作：重试本步骤、跳过、调整范围、保留部分结果、重新开始。
- 任务暂停后可从历史记录恢复，不能只靠页面刷新后的临时状态。

技术：

- 任务状态机至少支持 `draft / review / queued / running / paused / blocked / failed / partial / complete / cancelled`。
- 每一步使用幂等任务 ID 和执行记录，避免重复写入。
- 写入、分享和发布动作通过确认令牌或二次授权执行。
- 连接器和技能采用最小权限与可撤销授权。

验收指标：

- 首次任务计划确认率 ≥ 60%。
- 确认后的任务完成率 ≥ 70%。
- 异常任务可恢复率 ≥ 90%。
- 任务结果可追溯率 100%。
- 关键写入/分享动作误执行 0 次。

### Phase 3：结果沉淀与知识治理（第 7–10 周，P1）

目标：让一次 AI 工作变成下一次更快的企业资产。

产品：

- 结果进入新建文档、已有文档或知识库草稿。
- 写入前展示差异、来源、密级和目标位置权限。
- 文档版本、负责人、复核人和更新时间可见。
- 知识治理任务支持重复、过期、缺口、密级风险清单。
- 资产状态：草稿、待复核、已发布、已归档。

验收指标：

- 任务结果沉淀率 ≥ 30%。
- 沉淀后 7 天内被再次访问/引用的资产比例 ≥ 20%。
- 知识负责人处理治理清单的时间减少 ≥ 30%。
- 发布前密级/权限检查覆盖率 100%。

### Phase 4：组织化运营与规模化（第 10–12 周，P1）

目标：让管理员敢于开放、负责人能管理、团队能复制。

产品：

- 管理员审计：谁发起、谁确认、用了哪些来源、产生了什么写入。
- 角色权限：发起人、复核人、知识负责人、管理员。
- 使用分析：高频问题、无答案问题、任务失败原因、知识缺口。
- 连接器健康状态、授权到期提醒和撤销入口。
- 团队模板：把已验证的任务保存为可复用模板。

验收指标：

- 管理员能在 5 分钟内回答一次任务“谁做了什么”。
- 连接器授权异常发现时间 ≤ 15 分钟。
- 高频任务模板复用率 ≥ 25%。
- 周活跃目标用户中，至少 40% 完成过一次答案到资产的闭环。

## 5. 交付优先级

### P0：3.0 必须有

- 权限内检索和来源引用。
- 答案拒答与不确定性表达。
- 任务计划、确认、执行、暂停、失败和恢复。
- 高风险写入/分享/发布的逐项确认。
- 任务结果进入文档草稿并保留来源。
- 任务/回答历史与恢复。
- 核心埋点、审计日志和越权测试。

### P1：3.0 应该有

- 知识治理任务。
- 文档差异预览和版本管理。
- 角色化复核流。
- 连接器健康状态和模板复用。
- 无答案问题和失败任务分析。

### P2：3.0 之后再做

- 大规模专家市场和技能市场。
- 多模型自由切换。
- 复杂流程编排画布。
- 面向所有部门的全量连接器。
- 过度个性化的首页和装饰性视觉升级。

## 6. 关键页面/状态清单

3.0 设计评审不只看正常态，必须覆盖以下状态：

| 页面/模块 | 必须覆盖的状态 |
| --- | --- |
| 首页找答案 | 空范围、检索中、有来源、无来源、引用展开、沉淀确认 |
| 任务计划 | 草稿、待确认、范围调整、缺少资料 |
| 任务执行 | 排队、执行中、暂停、权限变化、连接器失败、部分完成、完成 |
| 结果沉淀 | 新建文档、追加文档、目标权限不足、密级待复核、成功写入 |
| 历史任务 | 可恢复、已取消、已失败、部分完成、来源失效 |
| 知识治理 | 重复、过期、缺口、公开风险、批量确认 |
| 移动端 | 单列、44px 点击目标、长文本换行、工具栏横向滚动 |

## 7. 埋点与指标体系

### 北极星指标

**每周完成至少一次“答案/任务 → 人工确认 → 结果沉淀”的有效工作会话数。**

### 漏斗指标

1. 进入 AI 工作台。
2. 提交目标/问题。
3. 看到可验证来源。
4. 确认任务或接受答案。
5. 完成结果。
6. 沉淀为文档/知识资产。
7. 资产再次被引用。

### 质量指标

- 权限越权率。
- 来源错误率。
- 无来源却给出确定结论的比例。
- 任务失败率与恢复率。
- 高风险动作误执行率。
- 用户人工返工时长。

## 8. 团队拆分建议

| 角色 | 负责范围 |
| --- | --- |
| 产品 | 3 个核心场景、状态机、确认规则、指标定义 |
| 设计 | 正常态 + 异常态 + 移动端 + 任务/引用/沉淀流程 |
| 前端 | 三模式入口、任务时间线、结果沉淀、状态反馈 |
| 后端/AI | 检索权限、引用、任务编排、幂等执行、模型调用 |
| 知识/安全 | 密级、角色、审计、数据保留和越权测试 |
| QA | 场景矩阵、回归、权限攻击、异常恢复、跨端验收 |
| 运营 | 种子团队、模板库、无答案问题和失败任务复盘 |

## 9. 版本门控

### Alpha 门控

- 3 个核心场景可走通。
- 所有回答有来源或明确拒答。
- 任务能暂停、失败和恢复。
- 高风险动作默认不自动执行。

### Beta 门控

- 5–10 个种子团队连续使用两周。
- P0 指标达到目标的 70% 以上。
- 无权限越权和高风险误写入事故。
- 失败任务和无答案问题有每周复盘机制。

### GA 门控

- P0 指标达到目标。
- 审计、数据保留、撤销授权、版本恢复完成。
- 移动端、无障碍和关键浏览器验收通过。
- 运营手册、管理员手册和用户引导完成。

## 10. 明确不做的事情

- 不把首页继续做成纯营销式 AI 启动页。
- 不在没有权限、审计和幂等能力前开放自动写入/分享。
- 不先扩充连接器数量，再回头补核心闭环。
- 不用“模型更聪明”代替可测量的来源质量和任务完成率。
- 不把所有企业知识库一次性迁移作为 3.0 前置条件。

## 11. 需要尽快确认的三个产品决策

1. **3.0 首发场景**：建议锁定“项目周报/风险汇总”和“制度问答”，知识治理作为第二个种子场景。
2. **自动化边界**：建议 3.0 默认只读 + 草稿写入；正式发布、外部分享、删除必须人工确认。
3. **首批用户范围**：建议选择 1 个项目团队、1 个职能团队、1 个知识负责人团队，而不是全组织同时开放。

## 12. 版本结论

推推 3.0 的成功不应是“页面看起来更完整”，而应是：

> 一个真实企业用户可以在权限边界内，用推推完成一次从问题到结果、从结果到资产的工作，并且任何关键动作都能解释、确认、恢复和审计。

这条标准通过，3.0 才值得扩大连接器、技能和专家生态；否则继续扩展功能只会放大复杂度。
